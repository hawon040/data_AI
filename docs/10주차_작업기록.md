## 1. 서비스키 유출 방지 점검 (2026-11-05)

**한 일**
- 코드가 서비스키를 읽는 방식을 확인했다. `tourism_platform/.../datagokr_client.py`는 `os.environ.get()`로, `web/api/seasonal-landscapes.ts`는 `process.env.TOUR_API_SERVICE_KEY`로 읽는다. 둘 다 환경변수만 쓴다.
- 저장소 전체(.py/.ts/.tsx)를 검색했지만 하드코딩된 키는 없었다.
- `.env`를 무시하는 설정이 `web/.gitignore`에만 있었다. 그래서 저장소 루트에 `.gitignore`를 새로 만들어 `.env`와 `.env.*`를 무시하게 했다(`.env.example`은 예외로 남김).

**실행 명령**
```bash
git ls-files | grep -i env
grep -rnE "serviceKey=[A-Za-z0-9%]{20,}" --include=*.py --include=*.ts --include=*.tsx .
git check-ignore -v .env tourism_platform/.env web/.env
```

**결과 수치**
- git이 추적하는 env 관련 파일: 1개(`web/.env.example`, 실제 키 없이 자리표시자만 있음)
- 하드코딩된 키: 0건
- 무시 설정 확인: `.env`, `tourism_platform/.env`, `web/.env` 3곳 모두 git이 무시함

**오류와 해결**
- 문제: 루트나 `tourism_platform/`에 `.env`를 만들면 커밋에 포함될 수 있었다.
- 해결: 루트에 `.gitignore`를 추가했다.

## 2. api.py를 저장소에 추가 (2026-11-05)

**한 일**
- 내 PC에만 있던 공공데이터 조회 웹 `api.py`(로컬 `tourapi/` 폴더)를 `tools/api.py`로 복사해 저장소에 넣었다. 원본은 Vercel 배포에 쓰이므로 그대로 두었다.
- 키가 하드코딩된 곳이 있는지 점검했다. `API_KEY`와 `KCISA_API_KEY`는 둘 다 `os.environ.get()`로 읽는다. `MONGO_URI`도 환경변수로 읽고, 기본값은 `mongodb://localhost:27017`라 계정 정보가 없다.
- "인증키를 입력하세요"라고 적혀 있던 주석 2줄을 "환경변수로 설정하세요"로 고쳤다. 코드에 키를 직접 쓰도록 유도하지 않기 위해서다.
- 원본 폴더의 `.env.local`(Vercel 토큰)은 복사하지 않았다.

**실행 명령**
```bash
cp ../tourapi/api.py tools/api.py
grep -nE "KEY|environ|getenv" tools/api.py
grep -nE "serviceKey=[A-Za-z0-9%]{20,}|[A-Za-z0-9%+/]{40,}={0,2}" tools/api.py
API_KEY= KCISA_API_KEY= python -c "...tools/api.py import..."
```

**결과 수치**
- 파일 크기: 2,068줄
- 키를 읽는 곳 3곳(`API_KEY`, `KCISA_API_KEY`, `MONGO_URI`), 모두 환경변수
- 긴 토큰 패턴 검색 결과 1건(52행). 확인해 보니 KCISA API 주소(`.../convergence2018/conver10`)여서 키가 아니었다. 하드코딩된 키는 0건이다.
- 키 없이 import해도 성공했다(`API_KEY set: False`). 키가 없으면 `_require_key()`가 요청할 때 오류를 알려 준다.

**오류와 해결**
- 별도 오류는 없었다. `api.py`는 다른 파일을 상대경로로 읽지 않아서 `tools/` 폴더에서도 그대로 실행된다(`python tools/api.py`).
