## 1. 서비스키 유출 방지 점검 (2026-11-05)

**한 일**
- 코드가 서비스키를 읽는 방식을 확인했다. `tourism_platform/.../datagokr_client.py`는 `os.environ.get()`로, `web/api/seasonal-landscapes.ts`는 `process.env.TOUR_API_SERVICE_KEY`로 읽는다. 둘 다 환경변수만 쓴다.
- 저장소 전체(.py/.ts/.tsx)를 검색했지만 하드코딩된 키는 없었다.
- `.env`를 무시하는 설정이 `web/.gitignore`에만 있었다. 그래서 저장소 루트에 `.gitignore`를 새로 만들어 `.env`와 `.env.*`를 무시하게 했다(`.env.example`은 예외로 남김).

**실행 명령**
```bash
git ls-files | grep -i env
grep -rnE "serviceKey=[A-Za-z0-9%]{20,}" --include=*.py --include=*.ts --include=*.tsx .
git check-ignore -v .env tourism_platform/.env web/.env
```

**결과 수치**
- git이 추적하는 env 관련 파일: 1개(`web/.env.example`, 실제 키 없이 자리표시자만 있음)
- 하드코딩된 키: 0건
- 무시 설정 확인: `.env`, `tourism_platform/.env`, `web/.env` 3곳 모두 git이 무시함

**오류와 해결**
- 문제: 루트나 `tourism_platform/`에 `.env`를 만들면 커밋에 포함될 수 있었다.
- 해결: 루트에 `.gitignore`를 추가했다.

## 2. api.py를 저장소에 추가 (2026-11-05)

**한 일**
- 내 PC에만 있던 공공데이터 조회 웹 `api.py`(로컬 `tourapi/` 폴더)를 `tools/api.py`로 복사해 저장소에 넣었다. 원본은 Vercel 배포에 쓰이므로 그대로 두었다.
- 키가 하드코딩된 곳이 있는지 점검했다. `API_KEY`와 `KCISA_API_KEY`는 둘 다 `os.environ.get()`로 읽는다. `MONGO_URI`도 환경변수로 읽고, 기본값은 `mongodb://localhost:27017`라 계정 정보가 없다.
- "인증키를 입력하세요"라고 적혀 있던 주석 2줄을 "환경변수로 설정하세요"로 고쳤다. 코드에 키를 직접 쓰도록 유도하지 않기 위해서다.
- 원본 폴더의 `.env.local`(Vercel 토큰)은 복사하지 않았다.

**실행 명령**
```bash
cp ../tourapi/api.py tools/api.py
grep -nE "KEY|environ|getenv" tools/api.py
grep -nE "serviceKey=[A-Za-z0-9%]{20,}|[A-Za-z0-9%+/]{40,}={0,2}" tools/api.py
API_KEY= KCISA_API_KEY= python -c "...tools/api.py import..."
```

**결과 수치**
- 파일 크기: 2,068줄
- 키를 읽는 곳 3곳(`API_KEY`, `KCISA_API_KEY`, `MONGO_URI`), 모두 환경변수
- 긴 토큰 패턴 검색 결과 1건(52행). 확인해 보니 KCISA API 주소(`.../convergence2018/conver10`)여서 키가 아니었다. 하드코딩된 키는 0건이다.
- 키 없이 import해도 성공했다(`API_KEY set: False`). 키가 없으면 `_require_key()`가 요청할 때 오류를 알려 준다.

**오류와 해결**
- 별도 오류는 없었다. `api.py`는 다른 파일을 상대경로로 읽지 않아서 `tools/` 폴더에서도 그대로 실행된다(`python tools/api.py`).

## 3. 날씨·미세먼지 API 연동과 분야별 API 파일 분리 (2026-11-05)

**한 일**
- `datasets.py` 한 파일에 있던 데이터셋 설정을 분야별로 나눴다(`tourism_platform/src/tourism_platform/data/apis/`).
  - `tourism.py`: 관광지·방문자 (데이터랩 방문자 수, TourAPI)
  - `safety.py`: 안전 (범죄·사고·화재·응급의료기관). 10주차부터 점수 계산에는 쓰지 않고 기록용으로 남김
  - `weather.py`: 기상청 단기예보·중기예보(육상·기온)·기상특보(특보현황) + 위경도→격자 변환
  - `air.py`: 에어코리아 측정소별 실시간 측정정보·측정소 목록
  - `datasets.py`는 네 파일을 합치는 역할만 한다. 그래서 `fetch_live`는 이전과 똑같이 동작한다.
- 엔드포인트와 파라미터는 공공데이터포털 상세페이지 5곳(15084084, 15059468, 15000415, 15073861, 15073877)에서 확인했다. 상세페이지에는 오퍼레이션이 한글 이름으로만 나와 있었다. 그래서 영문 오퍼레이션명은 키 없이 직접 호출해서 검증했다.
- 위경도→격자(nx, ny) 변환 함수 `latlon_to_grid()`와 역변환 `grid_to_latlon()`을 만들었다. 기상청 활용가이드의 Lambert 정각원추도법 상수(격자 5km, 기준점 38N·126E = (43,136))를 썼다.
- 관광지 좌표로 그날의 조건을 돌려주는 `get_spot_conditions()`를 만들었다(`data/spot_conditions.py`).
  - 단기예보: 강수확률(POP)·강수형태(PTY)·기온(TMP). 현재 시각이 속한 정시의 예보를 쓴다.
  - 기상특보: 특보현황 문구에 관광지 지역명(예: "강릉")이 있는지 본다. 특보는 좌표가 아니라 지역 이름으로 발표되기 때문이다.
  - 미세먼지: 측정소 목록에서 가장 가까운 측정소를 찾아 PM10·PM2.5 등급을 받는다.
  - 셋 중 하나가 실패해도 나머지 결과는 돌려주고, 실패 이유는 `errors`에 남긴다.
- `datagokr_client.fetch()`: 기상청·에어코리아는 오류를 XML로 돌려준다. 이때 JSON 파싱 오류 대신 응답 내용이 담긴 오류 메시지를 내도록 고쳤다.
- `fetch_live`: 날씨·대기질처럼 필수 파라미터가 있는 API는 예시 파라미터(서울시청 격자, 종로구 측정소)를 넣어 호출하게 했다.

**실행 명령**

## 4. 날씨 × 일행 추천 규칙 (web) (2026-11-05)

**한 일**
- 추천 규칙을 `web/src/lib/weatherRules.ts`에 만들었다.
  - 비·눈 예보 / 추운 날 / 더운 날 / 미세먼지 나쁨 → 실내만 추천
  - 호우·태풍·풍랑 특보 → 바다·산·계곡 제외
  - 날씨가 좋으면 실내·야외를 함께 추천하고, 비 소식(강수확률 30% 이상)이 있으면 지역마다 "비 오면 실내 대안"을 붙인다.
  - 어르신(60대 이상)이나 아이(10세 미만)가 있으면 strict 기준을 쓴다.
  - 방문일이 오늘부터 3일보다 멀면 "출발 2~3일 전에 다시 확인"을 안내한다.
- 기준값은 모두 `web/src/config/weatherThresholds.ts` 한 파일에 모으고, 각 값에 "팀 기준(안)" 주석을 달았다.
- 관광지 데이터에 실내/야외 구분이 없어서 `web/src/lib/attractionSetting.ts`에서 이름·분류의 키워드로 나눴다.
  - 실내 키워드: 박물관·기념관·동굴·시장·카페 등
  - 바다: 해변·해수욕장·○○항
  - 산: 국립공원·휴양림·산성·○○산
  - 키워드로 틀리는 곳(정동진, 주문진항, 대포항, 강원랜드 등)은 직접 지정했다.
  - 판단이 안 되면 야외로 본다. 날씨가 나쁠 때 실내라고 잘못 추천하는 쪽이 더 위험하기 때문이다.

  - 추천 목록 위에 날씨 판단 결과(실내 위주/특보 제외/함께 추천)와 근거, 안내를 보여 준다.
  - 실시간 날씨는 아직 web에 연결되지 않아서 시연용 예시 12개(`lib/weatherPresets.ts`)로 규칙을 확인한다.

- 문제 2: 데이터랩 API가 `INVALID_REQUEST_PARAMETER_ERROR(type)`를 돌려줬는데 "성공"으로 표시됐다.
  - 원인 ①: 클라이언트가 항상 `type=json`을 붙였다(데이터랩은 `_type`만 받는다).
  - 원인 ②: 데이터랩은 오류를 `response.header`가 아니라 최상위 `resultCode`로 준다.
  - 해결: 다른 형식 파라미터(`_type`·`dataType`·`returnType`)가 있으면 `type`을 붙이지 않고, 최상위 `resultCode`도 검사한다. 테스트 5개를 추가했다.
- 문제 3(샘플 데이터 오류): `sampleRegions.ts`의 속초시 코드가 51230(실제는 삼척시), 평창군 코드가 51830(실제는 양양군)이었다.
  - 해결: 데이터랩 실데이터의 시군구 이름으로 확인해 속초시 51210, 평창군 51760으로 고쳤다.
- 문제 4: 403 7건은 코드 문제가 아니라 활용신청 문제로 보인다. 공공데이터포털 마이페이지에서 해당 API 활용신청 상태를 확인해야 한다.
- 테스트: 파이썬 83개(기존 73 + TS 비교 4 + 클라이언트 6), 웹 39개 모두 통과했다.

## 19. tourapi 접근 로그 → Fluent Bit → MongoDB access_logs (2026-11-07)

**한 일**
- `api.py`의 `do_GET`이 요청마다 JSON 한 줄을 `tourapi/logs/access.jsonl`에 남긴다.
  - 항목: `ts`(로컬 시각 `%Y-%m-%dT%H:%M:%S`), `level`, `path`, `params`, `status`, `ms`
  - `level`: 5xx는 ERROR, 4xx는 WARN, 그 밖(200 등)은 INFO
  - 쿼리 값(위도·경도·서비스키 등)은 남기지 않는다. `params`에는 파라미터 이름만 정렬해서 넣는다.

  - 로그를 못 남겨도 응답은 그대로 보낸다. 예상하지 못한 예외는 500으로 응답하고 ERROR로 남긴다. 전에는 응답 없이 연결이 끊겼다.
  - `tourapi/.gitignore`에 `logs/`를, `.vercelignore`에 `logs`·`fluent-bit`를 넣었다.
- `tourapi/fluent-bit/fluent-bit.conf`, `parsers.conf`
  - 4주차 `C:\logslab` 설정과 같은 구조다: tail(JSON 파서 `json_ts`, `tail.db`, `storage.type filesystem`) → file 출력(`Format plain`), HTTP 서버 2020
  - 경로는 tourapi 기준 상대 경로다. 상태·버퍼·출력은 `logs/` 아래에 두어 커밋하지 않는다.
- `tourism_platform/src/tourism_platform/lake/access_log.py`
  - Fluent Bit 출력(`tourapi/logs/fluent-out/access.jsonl`)을 읽어 MongoDB `tourlink.access_logs`에 넣는다.
  - ts는 한국 시각을 UTC Date로 바꿔 저장한다. TTL 인덱스는 Date 필드에만 동작하기 때문이다.
  - `_id`는 줄 내용 해시와 같은 줄의 순번으로 만든다. 같은 파일을 다시 넣어도 중복되지 않는다.
  - 인덱스: `level_ts` {level: 1, ts: -1}, `ts_ttl_30d` {ts: 1, expireAfterSeconds 2592000}
  - aggregate로 경로별 요청 수·4xx 비율·오류율(5xx)·평균 응답시간을 출력한다. explain으로 `level=WARN` 최근 순 조회가 IXSCAN인지 확인한다.
