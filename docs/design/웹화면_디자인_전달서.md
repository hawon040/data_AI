# TourLink 웹 화면 디자인 전달서

디자인을 맡아 주는 친구에게 넘기는 문서입니다. 서비스가 무엇이고, 누가 어떻게 쓰고, 화면에 무엇이 반드시 나와야 하는지, 무엇은 바꾸면 안 되는지를 정리했습니다.
스크린샷(`images/`)은 **지금 구현된 화면**입니다. 완성된 디자인이 아니라 기능이 먼저 만들어진 상태라서, 정리와 개선이 필요한 곳이 많습니다.

---

## 1. 한 문단 소개

**TourLink**는 "누구와, 언제 떠나는지"를 입력하면 그날 날씨에 맞는 관광지를 추천하고, 가까운 응급실·대피소·관광안내소 같은 **대비 정보**까지 함께 보여 주는 웹 서비스입니다.
특히 **나이대가 다른 동행자**(어르신, 아이, 20대 친구 등)가 같이 갈 때, 한 사람만 좋아하는 곳이 아니라 **모두가 무리 없이 즐길 수 있는 곳**을 먼저 보여 주는 것이 핵심입니다.

## 2. 서비스가 약속하는 것 (화면이 전달해야 할 메시지)

1. **일행 모두를 위한 추천** — 동행자 중 가장 덜 맞는 사람을 기준으로 고릅니다. (예: 60대 + 20대가 같이 가면 두 사람 다 괜찮은 곳)
2. **그날 날씨를 반영** — 비·더위·추위·미세먼지가 심하면 실내 위주로, 특보가 있으면 바다·산·계곡을 뺍니다. 어르신·아이가 있으면 기준을 더 엄격하게 적용합니다.
3. **가기 전에 챙길 것을 알려 줌** — 준비물 체크리스트, 가까운 응급의료기관·대피소·관광안내소, 일행에게 필요한 무장애 편의 정보.
4. **광고 없는 추천, 근거를 보여 줌** — 협찬이나 리뷰 수가 아니라 공공데이터로 계산하고, "왜 이 곳인지"를 한 줄로 보여 줍니다.
5. **쓸수록 좋아짐** — 사용자가 동의하면 평가와 길찾기를 익명으로 기록해 다음 추천에 반영합니다.

## 3. 지금 상태와 방향 (꼭 읽어 주세요)

- 처음에는 **"지역 안전도 점수"** 로 시작했다가, 2026-11-05에 방향을 바꿔 **"날씨 + 일행 맞춤 추천 + 대비 정보"** 로 정했습니다. 안전 점수·등급 화면은 **의도적으로 숨겨 둔 상태**입니다. 이 화면을 되살리는 디자인은 하지 않습니다.
- 그래서 지금 화면의 일부 문구가 **이전 방향의 흔적**입니다. 예: 랜딩의 "어디로 떠날지, 얼마나 안전한지 한 번에", 상단 "안전 정보 안내", 띠 문구 "가고 싶은 관광지, 안전까지 확인하다". 새 방향("날씨와 일행에 맞는 추천 + 대비 정보")에 맞게 문구와 위계를 **함께 정리해 주세요.** 문구를 바꿀 때는 팀과 확인합니다.
- 지역 추천에 쓰는 성별·연령대 방문 데이터는 **아직 샘플**입니다. 화면에는 "또래 방문 1.4배" 같은 문장으로 나오는데, 실제 사용자 기록이 쌓이기 전까지는 예시 값입니다. 숫자를 크게 강조하는 디자인은 피하고, 근거 한 줄 정도의 무게로 다뤄 주세요.

## 4. 사용자와 사용 상황

- **누구**: 가족 여행(어르신·아이 동반), 세대가 다른 친구·가족 모임을 준비하는 사람. 여행 준비를 하는 사람이 대부분 **한 명이 대표로 입력**합니다.
- **언제**: 여행을 계획하는 중, 또는 출발 며칠 전 날씨를 확인할 때. 모바일로 보는 경우가 많을 것으로 가정하지만 **실제 접속 비율은 확인하지 못했습니다.** 모바일과 PC 모두 대응합니다.
- **상황**: 입력은 한 번에 끝내고 싶고, 결과에서는 "그래서 어디를 가야 하는지, 날씨 때문에 뭐가 바뀌었는지"를 빠르게 알고 싶어 합니다.
- **민감한 점**: 어르신·아이·응급 상황과 관련된 정보라서, 확정적인 표현("안전합니다")보다 **출처와 한계를 함께 밝히는 정직한 톤**이 중요합니다.

## 5. 핵심 사용 흐름

```
랜딩(/)  →  추천 도구(/app)
              ① (선택) 기록 참여 동의 여부 선택
              ② 여행 조건 입력: 방문일, 지역, 목적, 스타일, 교통편, 일정, 나와 동행자의 성별·연령대
              ③ [추천받기]
              ④ 방문일 날씨 안내 + 추천 지역 목록(근거 한 줄, 대표 관광지)
              ⑤ 관광지를 누르면 상세(길찾기, 체크리스트, 무장애 정보, 평가)
              ⑥ 다녀온 뒤 별점 평가 (동의한 경우)
```

## 6. 화면 목록

| 경로 | 화면 | 목적 | 스크린샷 |
|---|---|---|---|
| `/` | 랜딩 | 서비스 소개, [관광지 추천받기]로 `/app` 이동. 계절 사진이 5초마다 바뀌는 히어로 | `01_landing_pc.jpg`, `01_landing_mobile.jpg` |
| `/app` | 추천 도구 | 제품의 핵심 화면. 입력 → 결과 → 상세가 한 화면에서 이어짐 | `02_app_start_*.png`, `03_app_result_*.png`, `04_attraction_detail.png` |
| `/service` | 서비스 소개 | 기능 설명 | `05_service_pc.png` |
| `/methodology` | 방법론 | 추천이 어떻게 계산되는지 | `06_methodology_pc.png` |
| `/validation` | 검증 결과 | 정확도 수치(가상 데이터 시뮬레이션 결과임을 밝힘) | `07_validation_pc.png` |
| `/privacy` | 개인정보 처리방침(초안) | 기록 수집 항목·목적·철회 방법 | `08_privacy_pc.png` |

우선순위는 **`/app` > 랜딩 > 나머지** 입니다. `/service`, `/methodology`, `/validation`은 같은 템플릿(`LandingInfo`)을 공유하는 읽기용 페이지입니다.

## 7. `/app` 화면 구성 (가장 중요)

위에서 아래로 현재 배치는 다음과 같습니다. (PC는 2열, 모바일은 1열)

| 영역 | 내용 | 비고 |
|---|---|---|
| 기록 동의 패널 | "더 잘 맞는 추천을 위한 익명 기록" 안내와 [동의하고 참여] / [동의하지 않음], 처리방침 링크 | 선택 후에는 "기록에 참여 중 [참여 끄기]"로 줄어듦. 현재 폼 **위**에 있어 첫 화면을 밀어 내림 |
| 여행 조건 폼 ("누구와 떠나나요?") | 아래 7-1 | 항목이 13개 안팎이라 길다 |
| 지도 / 목록 (왼쪽 열) | 카카오 지도에 추천·주변 관광지 마커. 지도 키가 없으면 **목록 + 탭(관광지/반려동물 동반/의료관광)** 으로 대체 | 목록 대체 화면이 짧으면 왼쪽이 크게 비어 보임 |
| 날씨 안내 (오른쪽 열) | 7-2 | 결과의 첫 줄. 이 화면의 고유한 가치 |
| 기상특보 배너 | 선택한 지역에 특보가 있으면 경고, 같은 시도의 다른 지역 특보는 약하게 | `role="alert"` |
| 추천 여행지 목록 | 순위 카드 5개 + "이런 곳은 어때요? (탐색 추천)" | 7-3 |
| 날씨 때문에 빠진 곳 | 접이식 목록 "왜 빠졌는지" | 투명성 장치 |
| 관광지 선택 후 | 여행 체크리스트 → 상세 패널(길찾기·카카오맵 링크·이용 편의 정보·평가) | 7-4 |
| 아래쪽 | 계절별 여행지 캐러셀, 랜덤 여행(펜 던지기) | 부가 기능 |

### 7-1. 여행 조건 폼 항목

| 항목 | 선택지 |
|---|---|
| 방문일 | 날짜 |
| 여행 월 | 1~12월 (선택하면 계절 테마 색이 살짝 바뀜: 봄·여름·가을·겨울) |
| 여행 목적 | 전체 / 산행 / 체험·액티비티 / 축제·문화 / 바다·호수 / 산책·휴식 |
| 여행 스타일 | 스타일 전체 / 활동적인 여행 / 여유로운 여행 / 가족 여행 / 역사·문화 / 맛집·카페 |
| 도, 시·군·구 | 전국 또는 시범 지역(충남·충북·강원) |
| 교통편 | 대중교통 / 관광버스 / 자가용 / 도보·자전거 |
| 추천 순서 | 연령대·동행 선호 / 전체 인기 순 |
| 여행 일정 | 당일치기 / 1박 이상(1박 2일~3박 4일) |
| 나 | 성별(여성·남성) + 연령대(10대~60대 이상) |
| 동행자 | [+ 동행자 추가]로 같은 형식을 여러 명 추가 |
| 체크박스 | 내 성별·연령 생략 / 아이(10세 미만) 동반 / 야간 일정 |

- "내 성별·연령 생략"을 켜면 인기순으로만 추천합니다. 성별·연령은 추천 정확도를 위한 입력이지 **필수가 아님**을 느끼게 해 주세요.

### 7-2. 날씨 안내의 상태 (이 박스는 4가지 이상으로 달라집니다)

| 상태 | 제목 문구 | 의미 |
|---|---|---|
| 좋음 | "실내·야외를 함께 추천해요" | 제한 없음 |
| 실내 위주 | "실내 위주로 추천해요" | 비·눈, 폭염, 한파, 미세먼지 나쁨 중 하나 |
| 지형 제외 | "바다·산·계곡을 빼고 추천해요" | 호우·태풍·풍랑 등 특보 |
| 예보 없음 | "예보 확인 필요" | 방문일이 너무 멀거나 예보를 못 불러옴 |
| 불러오는 중 | "예보를 불러오는 중…" | 로딩 |

- 함께 표시되는 것: 출처(기상청, 에어코리아)와 발표 시각, 현재 기온(방문일이 오늘일 때), 미세먼지 등급, "방문일까지 3일 넘게 남아 예보가 바뀔 수 있어요" 안내, 어르신·아이가 있을 때 "기준을 더 엄격하게 적용했어요" 안내.
- `주소 뒤에 ?demo=weather`를 붙이면 **시연 모드**가 켜져 예시 날씨를 고를 수 있습니다(맑음, 비, 눈, 한파, 폭염, 미세먼지, 호우특보 등 12가지). 디자인 확인에 쓰세요. 시연 모드에서는 "(시연 모드)" 라벨이 반드시 보입니다.

### 7-3. 추천 카드에 들어가는 정보

- 순위 번호, 지역 이름과 시도, 근거 한 줄(예: "해변 카페거리 — 전 연령대가 찾지만 특히 20대 비중이 압도적"), 또래 방문 배수("또래 방문 1.4배"), 대표 관광지 칩 4~6개, 날씨 한 줄 요약(날씨 때문에 바뀐 경우만), 무장애 정보가 있는 관광지의 "편의 정보" 배지.
- 선택된 카드는 파란 테두리로 강조됩니다.
- 사용자 기록이 쌓인 지역에는 "이 서비스 사용자 기록 N건 반영 (P%)" 줄이 추가됩니다.

### 7-4. 관광지 상세에서 보여 주는 것

| 블록 | 내용 |
|---|---|
| 기본 | 이름, 분류, 인기 지표, 태그, 좌표, 주소·전화(지도 키가 있을 때) |
| 사용자 평가 | "20대 평균 4.3점 (6건)". **평가가 5건 미만이면 점수를 숨기고** "평가가 아직 적어 점수를 표시하지 않아요" |
| 길찾기 | 카카오맵 길찾기(새 탭), 카카오맵에서 보기 |
| 이용 편의 정보 | 일행에게 필요한 시설 중 정보가 등록된 비율, "있음 / 등록 정보 없음" 목록, 출처 |
| 평가 | 별점 1~5 + [평가 보내기] + 결과 메시지. **동의한 사용자에게만** 보임 |
| 여행 체크리스트 | 날씨와 관광지 종류(바다·산·계곡)에 맞는 준비물, "참고용" 표시 |

## 8. 화면 상태 목록 (빠뜨리기 쉬운 것)

| 대상 | 상태 |
|---|---|
| 지도 | 정상 / 지도 키 없음 또는 불러오기 실패 → 목록으로 대체 ("지도를 불러오지 못했어요. 아래 목록에서 장소를 확인하세요.") |
| 공공데이터 | 불러오는 중 / 실패("실시간 정보를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.") — 칸별로 따로 실패할 수 있음 |
| 추천 목록 | 입력 전("여행 조건을 정하고 동행자를 입력한 뒤 추천받아 보세요.") / 결과 있음 / 결과 없음(조건 완화 안내, 날씨 때문에 없을 때는 다른 문구) |
| 날씨 | 위 7-2의 5가지 + 특보 배너 + 인근 특보 |
| 기록 동의 | 아직 안 물음 / 참여 중 / 참여 안 함 |
| 평가 | 입력 전 / 저장됨 / 오늘 이미 평가함 / 요청 많음 / 저장 못 함 / 동의 안 해서 숨김 |
| 무장애 정보 | 불러오는 중 / 매칭 실패 / 정보 없음 / 있음 |
| 접근성 | 모션 줄이기 설정(`prefers-reduced-motion`)이면 캐러셀 자동 전환과 전환 애니메이션을 끔 |

## 9. 반드시 지켜 주세요

1. **출처와 한계를 화면에서 지우지 않습니다.** "출처: 기상청", "참고용", "(시연 모드)", "등록 정보 없음은 시설이 없다는 뜻이 아니에요" 같은 문구는 정직성의 핵심입니다. 모양은 바꿔도 되지만 사라지면 안 됩니다.
2. **평가 점수는 5건 이상일 때만** 보입니다(개인정보 보호 약속). 디자인에서 점수 자리를 비워 두지 말고 "아직 적어요" 상태를 설계해 주세요.
3. **기록 동의는 선택이고, 거절해도 모든 기능이 똑같이 동작합니다.** 거절을 불편하게 만들거나 어둡게 유도하는 디자인(작은 거절 버튼, 흐린 색 등)은 하지 않습니다.
4. **개인정보 안내 문구**("이름·연락처·위치는 저장하지 않아요")는 실제 동작과 같은 내용입니다. 바꾸려면 팀에 확인합니다.
5. **안전 점수·등급 UI는 만들지 않습니다.** 대비 정보(응급실·대피소·안내소 거리, 체크리스트)로 표현합니다.
6. **불안을 키우는 표현을 피합니다.** 경고(`role="alert"`)는 실제 특보가 있을 때만, 그 외 상황은 차분한 안내로 구분해 주세요.
7. **접근성**: 색만으로 상태를 구분하지 않기, 키보드 포커스 표시 유지(현재 3px 파란 윤곽선), 별점 버튼은 `role="radio"`와 라벨(`1점`~`5점`), 충분한 글자 대비. 어르신이 쓸 가능성이 있어 **글자 크기와 터치 영역**을 넉넉하게 부탁드립니다.

## 10. 현재 디자인 시스템 (코드 기준)

- **색**: `web/src/theme.css`의 변수. 밝은 테마가 기본입니다.
  - 배경 `#f7f9fc`, 면 `#ffffff`, 보조 면 `#f0f4fa`, 글자 `#172033` / 보조 `#526078` / 흐림 `#748096`
  - 강조 파랑 `#3563d9`, 청록 `#087f75`, 위험 `#c2413b`, 대표 그라데이션 파랑→청록
  - 등급 5색(`--grade-1`~`5`)은 안전 등급용이라 지금은 쓰지 않습니다.
- **글꼴**: Pretendard → Noto Sans KR → DM Sans.
- **버튼**: 알약형(`pill-button`, `pill-mini`). 주 버튼은 그라데이션, 보조는 테두리만.
- **반응형**: 중단점이 파일마다 다릅니다(400 / 600 / 680 / 720 / 900 / 1000px). 정리하면 좋습니다.
- **계절 테마**: 여행 월에 따라 `/app` 배경에 계절 색 번짐(`--season-wash`)이 깔립니다.
- CSS 프레임워크나 컴포넌트 라이브러리는 **쓰지 않습니다.** 일반 CSS 파일입니다(`web/src/pages/*.css`, `theme.css`). 디자인 시스템을 새로 정리해도 좋지만, 기존 클래스 이름을 쓰는 코드가 많아서 **교체 범위를 먼저 개발자와 상의**해 주세요.

## 11. 제가 보기에 개선이 필요한 곳 (디자인 의견을 기다립니다)

1. **문구와 방향 불일치** — 3장 참고. 랜딩 히어로·상단 링크·띠 문구가 "안전" 중심입니다.
2. **입력 폼이 길다** — 모바일에서 폼이 화면 두 장 가까이 되어 결과가 한참 아래에 나옵니다(`03_app_result_mobile.png`). 꼭 필요한 입력(방문일, 지역, 나와 동행자)과 선택 입력(목적, 스타일, 교통편 등)을 나누는 구성이 필요해 보입니다.
3. **기록 동의 패널 위치** — 첫 화면의 가장 위에서 핵심 입력을 밀어 냅니다. 입력 직후나 결과 근처, 또는 한 번만 뜨는 안내 등 대안을 제안해 주세요.
4. **결과 위계** — 결과에서 가장 먼저 보여야 할 것(날씨가 추천을 어떻게 바꿨는지)과 부가 정보(체크리스트, 무장애, 평가)의 우선순위가 한 열에 섞여 있습니다.
5. **지도가 없을 때의 레이아웃** — 왼쪽 열이 목록 몇 줄로 끝나서 큰 빈칸이 생깁니다. 지도는 카카오 키가 있어야 나오기 때문에 이 상태도 정식 화면으로 설계해야 합니다.
6. **PC에서 정보 밀도** — 추천 카드 목록이 작은 영역 안에서 스크롤됩니다.
7. **랜딩** — 히어로 이후 영역이 길고 설명 위주입니다. "한 번 입력하면 날씨까지 반영해 준다"를 보여 주는 장면(예: 비 오는 날 추천이 바뀌는 비교)이 있으면 좋겠습니다.
8. **브랜드** — 로고는 "T" 글자 아이콘 + TourLink 텍스트가 임시로 들어 있습니다.

## 12. 직접 띄워 보는 방법

```bash
cd web
npm install
npm run dev            # http://localhost:5173/app
```

- 서버(`tourapi`)가 없으면 날씨·무장애·목록이 "불러오지 못했어요"로 나옵니다. 배포된 서버를 쓰려면 `web/.env.local`에 아래를 넣습니다.
  ```
  TOURAPI_PROXY_TARGET=https://tourapi-demo.vercel.app
  VITE_KAKAO_MAP_KEY=<카카오 JavaScript 키>
  ```
  카카오 키는 팀에서 받고, 카카오 개발자 콘솔에 `http://localhost:5173`을 등록해야 지도가 뜹니다. 키는 파일에만 넣고 공유 채널이나 커밋에 올리지 마세요(`.env.local`은 git이 무시합니다).
- 날씨 상태를 바꿔 보려면 `http://localhost:5173/app?demo=weather`.
- 기록 평가 박스를 보려면 동의 패널에서 [동의하고 참여]를 누른 뒤 추천받기 → 관광지 선택.
- 저장소에는 정적 시안이 없습니다. Figma를 쓰신다면 위 스크린샷을 출발점으로 삼아 주세요.
