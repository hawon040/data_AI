## 10주차 (11/5 ~ 11/6) · TourLink로 방향 전환
**목표:** 일행과 날씨에 맞는 추천과 대비 정보로 서비스 방향을 바꾼다.

**한 일**
- 서비스키 유출 점검, `api.py`를 저장소에 추가하고 `.env` 무시 설정
- 기상청 날씨·에어코리아 미세먼지 API 연동, API 설정을 분야별 파일(날씨·대기질·안전·관광)로 분리
- **날씨 × 일행 추천 규칙** 구현 (비·기온·미세먼지 → 실내만, 특보 → 바다·산·계곡 제외, 어르신·아이 동반 시 엄격 기준)
- **대비 정보:** 가까운 응급의료기관·지진해일대피소·관광안내소와 하버사인 거리
- 지역 안전도 점수 숨김, 추천 근거를 핵심 수치 한 줄로 정리
- **알고리즘 검증:** 파이썬↔웹 지수 일치 테스트, 실데이터 호출 값과 샘플 값 비교, 수식↔코드 대조
- **수업 도구 적용:** 데이터 레이크(raw→processed→gold), MongoDB 실습(ESR 인덱스 explain, 2dsphere `$geoNear`, aggregate↔pandas), API 호출 로그
- 범죄 통계 제거, 옛 샘플 대시보드 정리, `api.py`를 `tourapi/`로 통합, GitHub Pages 대시보드 복구
- 날씨 맞춤 추천을 `api.py`에 연결 (단기·중기예보, 특보, 미세먼지)

**결과 수치:** 데이터 레이크에서 관광지 897건 중 중복 36건을 제거해 861건, 지진해일대피소 1,522건 중 629건을 사용. 기상청 API는 첫 실행에서 403 5건(활용신청 승인 전).

**겪은 문제:** 전국관광지 API가 `response` 없이 `header/body`만 반환해 `KeyError` → 클라이언트에서 같은 모양으로 변환. 서비스키는 Encoding이 아니라 Decoding 키를 써야 함.

## 11주차 (11/7 ~ 11/10) · 실제 예보 연결과 무장애·배포
**목표:** 판정 규칙에 실제 예보를 연결하고, 일행 맞춤 정보와 운영을 보강한다.

**한 일**
- **웹 추천에 실제 기상청·에어코리아 예보 연결**, 몇 박 며칠 일정의 날짜별 판정, 날씨 때문에 제외된 곳 목록, 초단기실황, 기상특보 배너(같은 시도 인근 특보는 약하게 표시), 미세먼지 등급·마스크 안내
- 시도별 시군구 선택, 강원 영서·영동 구분, 전남광주 통합 명칭 대응
- **무장애 정보 연동**(`KorWithService2`): 일행 맞춤 편의 정보, 추천 카드 배지, 상세 패널, 일행에게 필요한 시설 정보 등록 비율
- 준비물 체크리스트(날씨 + 바다·산·계곡 관광지 종류별 한 줄)
- 반려동물 동반·의료관광 목록 탭, 전국 목록에서 도 선택 안내, 지도 대신 목록을 도·추천 지역 기준으로 정리
- **운영:** 날씨·무장애 결과를 MongoDB에 캐시(날씨 1시간, 무장애 6시간), `tourapi` 접근 로그를 Fluent Bit → MongoDB `access_logs`(TTL 30일), `tourapi` 재배포, `npm run dev:all`로 서버와 웹 동시 실행
- 보행자 사고·화재·영문 관광정보 설정 제거, 소개 페이지 정리(`/about` 삭제)
- 검증 수치 재현: 추천 정밀도는 가상 세계 100개 평균으로 정함 (결합 0.392 대 인기순 0.183, 2.1배)
- 수업 도구 → 프로젝트 적용 연계표 작성 (`docs/근거자료.md` 6절)

**검증:** 파이썬↔웹 600개 값 모두 상대오차 1e-12 이하(최대 3.85e-16), pytest 98개·웹 64개 통과(11/7 기준).

**겪은 문제:** 배포 환경의 Vercel에는 `MONGO_URI`가 없어 메모리 캐시로 동작한다. 웹과 `tourapi`는 GitHub 푸시로 자동 배포되지 않아, 코드를 바꾼 뒤 각각 직접 재배포해야 한다.

## 11주차 이후 (11/10) · 수업 도구 단계별 적용
**목표:** 수집·전처리·저장·캐시·분석 단계에 기능에 맞는 도구를 하나씩 적용한다.

| 단계 | 도구 | 한 일 | 확인 |
|---|---|---|---|
| 수집 | Fluent Bit | 공공데이터 호출 로그(`api_calls.jsonl`)를 접근 로그와 분리해 수집, 시간 형식 파서 추가, 실행 뒤 입력·출력 비교 점검(`fluent_check`) | 설정 정적 점검과 읽기·중복 방지 테스트 통과. Fluent Bit 실행은 로컬에서 확인 필요 |
| 전처리 | pandas, Jupyter | 정제 규칙별 걸러진 건수·빈 칸·이상치 리포트와 정제 노트북 | 테스트 5개 통과. 노트북은 합성 데이터로 끝까지 실행 확인, 실데이터 실행은 전 |
| 저장 | MongoDB | `api_calls` 컬렉션, 복합 인덱스, 30일 TTL | 적재 확인. 집계·인덱스는 실제 MongoDB에서 확인 필요 |
| 캐시 | Redis | 메모리 → Redis → MongoDB → API 순 조회, 만료(TTL), 동시 갱신 방지 잠금, 단계별 적중 수(`/api/cache/status`) | 실제 redis-server로 테스트 통과, 실제 서버에서 Redis 연결 확인. 배포 환경은 `REDIS_URL` 설정 전 |
| 분석 | Orange | 관광지 58곳 CSV, 진행 순서, 규칙·Orange 정확도 비교 스크립트 | 테스트 6개 통과. 정답 입력 전이라 정확도는 미측정 |

- 사용자 기록 기반 추천: `tourism_platform/usage/`(기록 검증·집계·지역 LQ·평가 보정), `tourapi/usage_events.py`(저장·요약·요청 제한), 웹 동의 안내·별점·길찾기 기록과 추천 반영. 파이썬↔TS 계산 일치 테스트, HTTP 전 구간 테스트, 브라우저 확인 완료
- 전체 테스트: 파이썬 119개 통과(2개는 MongoDB 서버가 없어 건너뜀), 웹 빌드 통과·테스트 78개 통과
- 브랜치 `claude/gifted-tesla-v11l12`에 있고 `main`에는 아직 합치지 않았다.
