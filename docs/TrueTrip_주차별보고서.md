## 1주차 (9/28 ~ 10/4) 핵심 방법론 구현과 웹 MVP

**목표:** 신청서의 방법론을 코드로 구현하고, 웹에서 동작하는 MVP를 만든다.

**한 일**
- 핵심 수식을 독립 파일로 구현: 특화지수(LQ), 동행자 최솟값 점수, 유효인구, 위해지수, 경험적 베이즈 축소 (`tourism_platform/`)
- 몬테카를로 교차검증 구현. 이 과정에서 버그 2개 발견·수정
  - 베이즈 축소에 인구 단위를 잘못 넘겨 축소가 작동하지 않던 문제
  - 3개년 평균의 표집분산을 나누지 않아 정확도가 떨어지던 문제
- 단위 테스트 23개 작성, 방법론 문서(`methodology.md`) 정리
- React + TypeScript + Vite 웹앱 구축, 수식을 TypeScript로 이식
- 랜딩(`/`)과 추천 도구(`/app`) 분리, 지역 안 관광지 추천 추가
- 관광지 순위를 단순 인기가 아닌 방문자 인구통계 기반으로 계산
- 카카오 장소 조회와 길찾기 연결
- 투명성 페이지(`/about`) 작성, 이후 아틀라스 스타일로 재디자인 (발표용 품질)
- Vercel 배포, 직접 접속 시 404가 나는 문제를 SPA rewrite로 해결 (`vercel.json`)
- 카카오 카테고리 검색으로 지도에 실시간 주변 관광지 표시 (PR #1~#3)

**겪은 문제**
- Vercel 빌드에서 `vite: command not found` → Root Directory를 `web`으로 지정해 해결

## 2주차 (10/5 ~ 10/11) 관광지 확충과 공공데이터 수집 기반

**목표:** 지도에 보여줄 관광지를 늘리고, 실제 공공데이터를 받아올 구조를 만든다.

**한 일**
- 지역당 큐레이션 관광지를 3~4곳에서 5~6곳으로 확대 (10개 지역, PR #4)
- data.go.kr Open API 수집 스캐폴드 구축 (PR #5)
  - `datagokr_client.py`, 데이터셋 설정 레지스트리 `datasets.py`, 실행 CLI `fetch_live.py`
  - 키가 없으면 명확한 에러, 설정이 비어 있으면 호출하지 않는 구조
- 팀원 작업: GitHub Pages 대시보드 배포, 랜덤 여행지 추천 기능, 밝은 테마, 관광지 페이지 수정

**논의**
- 안전을 추천 카테고리에서 빼고 "이달의 안전 지역 순위"로 보여주자는 제안
- 안전·관광지 데이터를 매달 API로 갱신하는 방안 (GitHub Actions)
- 현재 웹 데이터는 샘플이며 실제 API 값이 아님을 확인
- 협업 권한 확인: 팀원 3명이 push 가능 (write 권한)

## 3주차 (10/12 ~ 10/18) 공공데이터 API 실연동

**목표:** 사용자가 승인받은 API를 하나씩 확인해서 설정에 연결한다.

**한 일** (모두 PR로 병합)
- **PR #6** 경찰청 범죄 발생 지역별 통계 연결. `odcloud` 요청 방식 추가 (파라미터 `page/perPage`, 평탄한 응답 구조)
- **PR #7** 전국관광지정보표준데이터, 전국관광안내소표준데이터 연결
- **PR #8** 국립중앙의료원 응급의료기관 위치정보 연결 (공식 HWP 문서에서 `getEgytLcinfoInqire` 확인)
- **PR #9** 한국관광공사 DataLabService 방문자 수 연결. 성공 코드 `"0000"`을 오류로 처리하던 버그 수정
- **PR #10** 경찰청 범죄 발생 장소별 통계 연결 (2023년부터 장소 분류 64개, λ_k 계산용)
- 설정 현황: 9개 데이터셋 중 6개 연결, pytest 30개 통과

**중요한 발견**
- DataLabService에는 **성별·연령 분포가 없다** (시군구×요일×방문자유형만 제공). 성·연령 기반 특화지수의 전제가 바뀔 수 있어 `visitor_by_gender_age`는 미설정으로 두었다.
- 서비스키는 공개 저장소에 올리지 않고 환경변수로만 사용한다.

## 4~5주차 (10/19 ~ 10/31) 데이터 한계 대응과 맞춤 추천 설계 (커밋 없음)

**목표:** 성·연령 데이터가 없는 문제를 풀고, 사용자 데이터로 정교화하는 구조를 설계한다.

**논의와 결정**
- 성·연령 데이터 확보 후보: 데이터랩 웹 다운로드 / 네이버 데이터랩 검색어트렌드 API
- SNS·블로그 후기에서 성·연령을 추정하는 방안은 **제외**: 광고 없는 추천 원칙에 어긋나고 정확도·약관 문제가 있음
- 월별 인기 관광지: 후보 목록은 관광지 표준데이터에서, 월별 관심도는 데이터랩에서 가져오는 방식 선택
- 데이터랩 웹 다운로드에서 10개 시범 지역의 실제 시군구 방문자 합계 확보 (청주시 121,752,354 등). 아직 웹에 반영 전
- 보행자 사고·화재 통계는 사용하지 않기로 결정
- **평가 기반 맞춤 추천 설계 완료**
  - 초기 공공데이터 → 사용자 평가가 쌓이면 성별·연령대별 맞춤으로 전환
  - 평가 수만큼 기존 가중치를 실측값으로 조정 (경험적 베이즈 방식)
  - 동행자 중 최저 선호도 기준 유지, "같이 즐거움 지수" 추가
- 차별성 정리와 종합 보고서(`docs/TrueTrip_종합보고서.md`) 작성
