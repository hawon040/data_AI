# TrueTrip 종합 보고서

> 나이 차이가 많아도 같이 즐거운 여행 — 동행자 전원이 만족하는 안전한 관광지 추천 플랫폼

---

## 1. 서비스 개요

동행자의 성별·연령대를 입력하면, 공공데이터로 계산한 지역별 방문 특화도와 안전지수를 바탕으로 지역과 관광지를 추천합니다. 한 사람이 아니라 **동행자 전원**을 기준으로 삼는 것이 핵심입니다.

| 구성 | 내용 |
|---|---|
| `tourism_platform/` | Python 패키지. 추천·안전 수식, 데이터 수집 클라이언트, 검증 코드 (pytest 30개) |
| `web/` | React 웹앱. 랜딩 `/`, 추천 도구 `/app`, 소개 `/about` |
| 배포 | Vercel (Root Directory = `web`) |

## 2. 차별성

1. **동행자 전체 기준 추천.** 동행자 중 가장 덜 만족할 사람의 점수를 기준으로 삼아, 한 사람만 좋아하는 곳이 위로 올라오지 않습니다.
2. **광고·협찬이 아닌 실제 이동 데이터.** 블로그·SNS 리뷰 대신 공공 방문자 데이터에서 계산한 특화도를 쓰고, "왜 이 지역인지"를 수치로 보여줍니다.
3. **안전을 추천 안에 포함.** 범죄·응급의료기관 접근성으로 지역 안전도를 계산합니다. 거주 인구가 아니라 관광객 체류 규모(유효인구)를 분모로 써서 관광객이 몰리는 지역의 위험이 과대평가되지 않게 하고, 아이·어르신이 있으면 그에 맞는 안전 항목을 먼저 보여줍니다.
4. **소규모 지역 보정.** 경험적 베이즈 축소와 3개년 평균으로, 표본이 작은 지역의 우연한 수치가 순위를 왜곡하지 않게 합니다.
5. **사용할수록 정확해지는 구조.** 공공데이터로 시작하고, 사용자 방문 평가가 쌓이면 성별·연령대별 맞춤 추천으로 옮겨 갑니다 (6장).
6. **지역 → 관광지 2단계 추천.** 동행자 조합에 맞는 지역을 먼저 고르고, 그 안에서 관광지를 추천합니다. 카카오 검색으로 주변 장소를 실시간으로 보여주고 길찾기를 연결합니다.

## 4. 현재 추천 계산식 (구현됨)

**지역 추천**
- 특화지수: `LQ_ig = (V_ig / V_i) / s_g` — 지역 i에서 그룹 g의 방문 비중을 전국 평균 비중으로 나눈 값
- 동행자 점수: `Score_i = min(LQ_i,g1, LQ_i,g2, …)` — 가장 덜 만족하는 동행자 기준

**지역 안 관광지 추천**
- `Match_a = Pop_a × min_p A(g_p, tags_a)` — A는 연령대별 관광지 유형 선호 가중치 (1.0이 평균, 현재는 가정값 표)

**안전 보정 (경험적 베이즈 축소)**
- `R̂_i = w·R_i + (1−w)·R̄`, `w = σ² / (σ² + R̄/P_eff)` — 표본이 작은 지역일수록 전국 평균 쪽으로 당김

## 6. 사용자 평가 기반 맞춤 추천

### 6-1. 단계별 전환

| 단계 | 추천 근거 |
|---|---|
| 초기 (사용자 데이터 없음) | 공공데이터 100% |
| 성장기 | 공공데이터 + 사용자 평가 (평가 수에 따라 비율 변화) |
| 성숙기 | 사용자 평가 중심, 공공데이터는 신규 지역·관광지의 기준 |

성숙기에는 같은 지역을 검색해도 20대 여성과 60대 남성에게 서로 다른 관광지가 추천됩니다.

### 6-2. 평가가 추천에 반영되는 과정

1. **추천:** 동행자의 성별·연령대로 관광지를 추천합니다.
2. **평가:** 여행 후 동행자 각자가 방문한 관광지에 1~5점을 매깁니다. 방문 인증된 평가만 반영합니다.
3. **저장:** 관광지, 연령대, 성별, 점수, 방문일, 동행자 구성을 DB에 저장합니다.
4. **집계 (월 1회 자동):** 관광지별·연령대별 평균 점수를, 그 연령대가 평소 주는 평균과 비교합니다.
5. **조정:** 평가가 적으면 기존 가중치를 유지하고, 쌓일수록 실측값 쪽으로 옮깁니다.
6. **재추천:** 조정된 가중치로 다음 사용자에게 다시 추천합니다.
7. **반복:** 새 평가가 들어오면 4~6을 매달 반복하고, 오래된 평가는 비중을 줄입니다.

### 6-3. 계산식

```
weight_k = exp(−경과일수_k / 180)                 최근 평가에 더 큰 비중
n_ag     = Σ weight_k                             유효 평가 수 (a: 관광지, g: 연령대)
R̄_ag    = Σ weight_k · score_k / n_ag             가중 평균 점수
O_ag     = R̄_ag / R̄_g                            실측 선호도 (R̄_g: 연령대 g의 전체 평균)
w_ag     = n_ag / (n_ag + m)                      m = 10
A'_ag    = w_ag · O_ag + (1 − w_ag) · P_ag        P_ag: 기존 가중치, 0.6~1.4로 제한
Match'_a = Pop_a × min_p A'(a, g_p)               동행자 중 최저 선호도 기준
```

동행자가 2명 이상이면 "같이 즐거움 지수"를 추가로 반영합니다.

```
H_a     = (Σ min(한 방문의 점수들) + m·μ) / (n_trip + m)
Final_a = Match'_a × (H_a / μ)^0.5
```

**계산 예시** (60대, 카페형 관광지): 기존 P = 0.70, 평가 12건 평균 4.4점, 60대 전체 평균 3.8점
→ O = 1.16, w = 0.545, A' = 0.545×1.16 + 0.455×0.70 = **0.95**

| 평가 수 | 반영 비율 | 결과 |
|---|---|---|
| 0건 | 0% | 기존 추천 그대로 |
| 10건 | 50% | 기존값과 실측값 반반 |
| 50건 | 83% | 거의 실측값 |

### 6-4. 검증

- **오프라인:** 평가 20%를 떼어 두고 평가 반영 전후 추천을 비교 (NDCG@5, RMSE)
- **온라인:** 사용자 절반에게만 반영 버전을 보여주고 길찾기 클릭률과 재평가 점수 비교 (A/B)

### 6-5. 추가로 필요한 것

- 평가 저장용 DB와 평가 입력 화면
- 월 1회 집계 스크립트 (GitHub Actions + Python)와 조정 가중치 파일 생성
- 성별·연령을 저장하므로 개인정보 처리방침
- 평가 5건 미만인 관광지는 평가 지표를 숨기는 최소 노출 기준
