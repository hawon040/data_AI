# 관광 추천 웹앱 (MVP)

창업 도전신청서 5.1~5.2에서 정한 스택(React + TypeScript + 카카오맵 API)으로
만든 3단계 MVP 범위의 웹앱이다: 지도 기반 웹앱, 동행자 교집합 추천, 사용자
조건 필터.

## 지금 상태

시범 권역(충청권 천안 포함 + 강원권 일부) 10개 지역의 **샘플 데이터**로
동작한다. 추천·안전도 계산 로직은 `tourism_platform`(파이썬) 패키지와 같은
수식을 `src/lib/`에 TypeScript로 옮겨 쓴 것이라 실제 데이터로 교체해도 로직은
그대로 쓸 수 있다.

## 실행

```bash
npm install
npm run dev
```

카카오맵을 보려면 [카카오 개발자센터](https://developers.kakao.com)에서
JavaScript 키를 발급받아 `.env.local`에 설정한다 (`.env.example` 참고):

```
VITE_KAKAO_MAP_KEY=발급받은_키
```

키가 없으면 지도 대신 지역 좌표 목록이 표시된다(폴백).

관광지 상세 패널(관광지 이름을 클릭하면 뜸)에서 실제 주소·전화번호까지
보려면, 같은 카카오 앱의 **REST API 키**를 추가로 발급받아 넣는다:

```
VITE_KAKAO_REST_API_KEY=발급받은_REST_키
```

REST 키가 없어도 "길찾기"·"카카오맵에서 보기" 버튼은 좌표만으로 항상
동작한다(카카오맵 웹 링크라 API 키가 필요 없다) — 주소·전화번호만 REST
키가 있을 때 추가로 뜬다.

## 화면 구성

- `/` — 랜딩 페이지 (`src/pages/Landing.tsx`). 짧은 핵심 문구와 함께 히어로 배경에서
  사계절 국내 관광지 사진이 천천히 자동 전환된다. 서비스·방법론·검증 결과 소개는
  메인에서 분리했으며, 왼쪽 상단 메뉴에서 항목을 선택하면 각 전용 화면(`/service`,
  `/methodology`, `/validation`)으로 이동한다. 상단 추천 CTA는 두지 않고, 메인의
  `관광지 추천받기` 버튼과 별도 자동차 버튼 중 하나를 누르면 자동차가 굴러가는
  애니메이션 뒤 추천 화면으로 이동한다. 안전지수 안내는 상단 메뉴에 표시하고
  메인 히어로에서는 제거한다. 서비스 소개 문구는 푸터에 배치한다.
  사진 위의 색상 오버레이는 단색으로 처리했으며
  대표 버튼 색은 계절 사진 색감에 맞춰 바뀌고 사진 출처와 이용 조건도 표시한다.
- `/service`, `/methodology`, `/validation` — 랜딩 소개 전용 화면
  (`src/pages/LandingInfo.tsx`). 왼쪽 상단 메뉴에서 각각 서비스 기능, 관광지 추천에서
  지역 안전 정보 확인으로 이어지는 방법, 시범 검증 지표를 따로 확인한다.
- `/app` — 실제 추천 도구 (`src/pages/AppPage.tsx`). 계절·여행 목적·스타일·지역·
  교통편·일정을 선택하고, 연령대 선호 또는 전체 인기도로 여행지를 추천받는다.
  계절 사진 슬라이드와 지도·관광지 상세·여행 준비 체크리스트도 제공한다.
  상단 "← TrueTrip"으로 랜딩 페이지로 돌아간다.
- `/about` — 구현 방식 & 데이터 신뢰성 (`src/pages/About.tsx`). 랜딩 페이지
  상단 "구현 방식 & 신뢰성" 버튼으로 들어간다. 신청서 구조(아이디어 →
  문제 발견 → 문제 정의 → 해결 방법)를 그대로 따라가며, 8개 섹션(문제 발견 ·
  문제 정의 · 시스템 구조 · 해결 방법 6가지 · 기술 스택 · 검증 결과 · 문제
  해결 기록 · 한계)을 스크롤 위치를 따라 강조되는 스티키 사이드바 목차로
  묶었다. hero 바로 아래에는 정밀도 2.5배·중복추천 82%↓ 같은 핵심 검증
  수치 4개를 카드로 먼저 보여주는 요약 바가 있어, 발표 자료로 인쇄(브라우저
  인쇄 → PDF 저장, `@media print` 스타일 적용됨)해도 첫 화면에서 결과가
  바로 보인다. 해결 방법 섹션의 카드 6개는 각각 발견한 문제 → 사용한
  데이터·API(실연동/샘플 대체/연동 예정 배지) → 왜 이 데이터인가 → 수식으로
  어떻게 조합했나 → 결과 수치 → 오차를 줄인 방법 순서로 정리했고, 카드
  제목 옆에는 핵심 성과를 한 줄로 뽑은 배지를 붙였다. 손으로 그린 SVG
  시스템 구조도(`src/components/ArchitectureDiagram.tsx`)로 요청이 브라우저
  →카카오 API/샘플 데이터→검증용 파이썬 패키지까지 가는 경로를 보여주고,
  기술 스택 표와 이 세션에서 실제로 겪은 버그 6개의 증상·원인·해결을 적은
  문제 해결 기록 표도 포함한다. 검증 과정에서 찾은 한계(발견한 오류, 단일
  순위를 안 쓰는 이유, 관광지 인기 지표가 근사치인 이유 등)를 숨기지 않고
  정리했다.

추천은 2단계로 이루어진다 (문서 4.3): 1단계는 지역을 동행자 교집합 점수로
고르고, 2단계는 그 지역 안의 실제 관광지를 골라 보여준다. 관광지 순위도
인기 지표 하나가 아니라 **동행자 연령대 선호도**(`lib/attractionAffinity.ts`)를
곱해서 계산한다 — 같은 지역이라도 60대 여성과 10대 남성이 입력하면 위에
뜨는 관광지 순서가 달라진다(예: 천안시 — 60대는 독립기념관이 위로, 10대는
병천순대거리가 위로). 추천이 나오면 1위 지역이 자동으로 선택돼 지도에
그 지역의 실제 관광지 이름표가 바로 뜨고(클릭 없이도), 지도가 없는 환경에서는
목록 폴백에도 지역명이 아니라 그 지역의 실제 관광지 이름이 표시된다.

랜딩 페이지 히어로 배경은 현재 계절의 국내 관광지 사진으로 시작해 사계절 사진을
9초 간격으로 부드럽게 전환한다. 추천 도구에서 여행 월을 바꾸면 봄·여름·가을·겨울
계절 테마와 관광지 사진이 함께 바뀐다.
여행 목적(산행, 체험, 축제·문화, 바다·호수, 산책)과 스타일(활동, 휴식, 가족,
역사·문화, 맛집·카페), 교통편, 당일치기 여부에 따라 샘플 관광지와 준비 안내를
필터링한다. 도 → 시·군·구 선택은 현재 제공하는 충청·강원 시범 데이터 안에서
동작하며, 읍·면이나 전국 단위 행정구역 정보는 아직 포함하지 않는다. 축제 일정,
실제 교통 소요 시간, 운영 시간은 연결된 데이터가 없어 공식 안내에서 확인해야 한다.

랜덤 여행은 안전 등급·지역 필터 없이 전체 시범 관광지 중 한 곳을 뽑고,
대한민국 지도 위 후보 핀을 표시한다. 뽑힌 관광지는 강조 핀과 안전 등급으로
구분하며, 지도 출처는 [`public/KOREA-MAP-CREDITS.md`](public/KOREA-MAP-CREDITS.md)에
기록했다. 추천 관광지를 고르면 지역·분류·인기도·관광지 성격 태그와 지도 링크를 보여주고,
여행 월·이동 수단·관광지 유형에 맞춘 일반 준비물 체크리스트를 표시한다. 계절
슬라이드는 선택한 월의 계절에 맞춰 진해·해운대·제주·내장산·태백산의 실제
관광지 사진을 자동으로 넘기며, 사진을 고르면 장소 설명과 카카오맵 길찾기를
제공한다. 사진 출처와 이용 조건은 각 사진 아래 및
[`public/seasonal/PHOTO-CREDITS.md`](public/seasonal/PHOTO-CREDITS.md)에 표시한다.
축제 사진은 과거 행사 사진일 수 있으며 현재 일정·운영을 뜻하지 않는다. 안전
등급은 순위를 정하는 기준이 아니라 참고 정보로 표시한다.

관광지 이름(지도 마커나 카드의 칩, 폴백 목록 어디서든)을 클릭하면 상세 패널이
뜬다 — `VITE_KAKAO_REST_API_KEY`를 설정했으면 카카오 로컬 API로 실제 주소·
전화번호를 가져오고, 어느 쪽이든 "길찾기"(카카오맵 길안내)와 "카카오맵에서
보기" 버튼으로 실제 위치를 찾아갈 수 있다 (`lib/kakaoLocal.ts`).

큐레이션한 관광지 10곳 안팎만으로는 다양성이 부족해서, 지역을 선택하면
카카오 로컬 API의 **카테고리 검색**(관광명소·문화시설·음식점·카페,
`findNearbyAttractions` in `lib/kakaoLocal.ts`)으로 그 주변의 실제 장소를
실시간으로 더 찾아온다. 같은 매치 점수 공식(`rankAttractions`)으로 정렬해
"주변에서 더 찾은 곳" 패널과 지도에 주황 점으로 따로 표시한다 — 인기 점수가
방문자 수가 아니라 검색 순위 기반 근사치라는 한계를 "실시간 · 참고용" 배지로
숨기지 않고 드러낸다. `VITE_KAKAO_REST_API_KEY`가 없으면 조용히 생략된다.

디자인은 밝은 배경과 블루/틸 액센트를 기본으로 하고, 여행 월에 따라 계절색이
은은하게 바뀐다 (`src/theme.css`, `src/pages/AppPage.css`).

## 구조

```
src/
├── theme.css               # 밝은 테마 공통 토큰 (색상, 필 버튼)
├── App.tsx                  # 라우터 (/ → Landing, /app → AppPage)
├── pages/
│   ├── Landing.tsx + .css   # 마케팅 랜딩 페이지
│   ├── About.tsx + .css     # 구현 방식 & 데이터 신뢰성 소개
│   └── AppPage.tsx + .css   # 실제 추천 도구 화면
├── lib/
│   ├── types.ts               # Person, Region, Attraction, SafetyIndex 등 도메인 타입
│   ├── indices.ts             # LQ·특화점수·그룹점수 (문서 4.2, 4.4)
│   ├── attractionAffinity.ts  # 연령대별 관광지 태그 선호 가중치 (문서 4.3 2단계 추천)
│   ├── kakaoLocal.ts          # 카카오 로컬 API 실제 장소 조회 + 길찾기/장소 링크
│   ├── recommend.ts           # 동행자 교집합 추천 + 관광지 매치 점수 + 탐색 추천(4.8)
│   ├── tripPreferences.ts     # 목적·스타일 필터, 계절 점수, 준비 팁
└── seasonalDestinations.ts # 계절 관광지·사진 출처·장소 정보
│   └── safetyPriority.ts      # 동행 구성별 안전 지표 표시 순서 (문서 4.5)
├── data/sampleRegions.ts  # 시범 권역 샘플 데이터
└── components/
    ├── CompanionForm.tsx      # 성별·연령대·동행자·필터 입력
    ├── SeasonalDiscovery.tsx  # 실제 국내 관광지 계절 사진 자동 슬라이드
    ├── TripPreparation.tsx    # 교통·일정·관광지별 일반 준비 체크리스트
    ├── RecommendationList.tsx # 추천 + 탐색 추천 카드 (관광지 칩 클릭 가능)
    ├── SafetyPanel.tsx        # 선택 지역의 안전 등급·지표
    ├── AttractionDetail.tsx   # 선택 관광지의 실제 주소·전화번호·길찾기
    └── MapView.tsx            # 카카오맵 (키 없으면 실제 관광지 이름 목록 폴백)
```

## 실데이터 연동 시 해야 할 일

1. `tourism_platform` 파이썬 패키지로 계산한 지역별 `groupVisitors`,
   `totalVisitors`, `safety` 값을 API나 정적 JSON으로 내보낸다.
2. `src/data/sampleRegions.ts`를 그 응답을 fetch하는 코드로 교체한다
   (`Region[]` 타입만 맞추면 나머지 컴포넌트는 그대로 동작한다).
3. 시범 권역 10곳 외 지역까지 넓힌다.
